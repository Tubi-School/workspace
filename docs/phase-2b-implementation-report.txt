================================================================================
D. MECHANICAL DEVIATIONS FROM docs/phase-2a-final-domain-design.txt
================================================================================

Exactly one deviation was required, and it is semantically inert:

1. Added an explicit relation field on SessionEntitlementSnapshot:

     subscriptionAccess SubscriptionAccess? @relation(fields: [subscriptionAccessId], references: [id])

   The design document's plain-text schema (section M) declared
   `subscriptionAccessId String?` on SessionEntitlementSnapshot and a
   corresponding `entitlementSnapshots SessionEntitlementSnapshot[]`
   back-relation on SubscriptionAccess, but never declared the `@relation`
   object connecting the two sides. Prisma requires an explicit relation
   field naming the foreign key before it will treat it as a navigable
   relation rather than a bare scalar column.

   This addition:
   - Introduces no new column, table, or constraint beyond what the design
     already specified (subscriptionAccessId was already a nullable
     foreign-key-shaped field in the design).
   - Does not change nullability, cardinality, or the ON DELETE behavior
     implied by the design (defaults to SET NULL for a nullable FK, matching
     the fact that a SessionEntitlementSnapshot's validity does not depend
     on the SubscriptionAccess row continuing to exist).
   - Does not alter any founder ruling, product rule, or attendance/
     entitlement semantics.

No other mechanical adaptations were necessary. Every nullable field, unique
constraint, non-unique index, and self-relation cardinality specified in the
frozen design transferred into valid Prisma schema syntax without further
adjustment.

No change was identified that would have altered product semantics. Nothing
was escalated as a blocker.

G. WARNINGS OR UNRESOLVED ISSUES
================================================================================

1. Turbo cannot spawn its binary in this environment.
   Running `pnpm run lint` from the repository root (which invokes
   `turbo run lint && eslint .`) fails immediately with:

     Error: spawn UNKNOWN
       at ChildProcess.spawn (node:internal/child_process:421:11)
       ...
       errno: -4094, code: 'UNKNOWN', syscall: 'spawn'

   This was reproduced identically in both Git Bash and PowerShell, and
   fails before Turbo dispatches to any package — it is a pre-existing
   local toolchain/environment issue, not something introduced by the
   Phase 2B schema or migration changes. It was NOT fixed as part of this
   milestone, per instruction to fix only issues directly caused by this
   implementation. Lint and build were instead verified by running the
   affected package's own scripts directly (`pnpm exec eslint .`,
   `pnpm run build` from within apps/api), which both succeeded. This
   should be investigated separately, since it currently blocks the
   repository's own root-level `pnpm lint` and (presumably) `pnpm build`/
   `pnpm typecheck` orchestration in this environment. CI runs on
   ubuntu-latest and may not reproduce this Windows-specific spawn failure,
   but that has not been independently confirmed in this session.

2. Prisma CLI update notice.
   `prisma validate` and other commands surfaced:
     "Update available 7.9.1 -> 8.0.0-rc.12 ... This is a major update"
   This is informational only. Per docs/architecture.md and
   docs/development.md, dependency versions in this repository are pinned
   deliberately, and no action was taken in response to this notice.

3. Scope boundary note (not a defect).
   SessionTeacher's exactly-one-PRIMARY invariant, WatchedInterval /
   LiveAttendanceInterval merge-on-write logic, coverage calculations, and
   SessionEntitlementSnapshot inheritance-copy logic are, per the frozen
   design and this milestone's explicit instructions, schema-only in
   Phase 2B. No service-layer code enforcing or computing any of these was
   written, and none was expected to be.
